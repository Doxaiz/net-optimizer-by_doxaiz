# Данные и разрешения

Net Optimizer работает без учётной записи и собственного сервера. Приложение не отправляет локальную историю или отчёты о сбоях автоматически. Это описание относится к текущему коду проекта; действия Android, операторов и сторонних сетевых сервисов регулируются ими отдельно.

## Что хранится на телефоне

- Настройки интерфейса и разрешённые пользователем предпочтения.
- История ручных сессий и временный черновик. После удаления приложения данные могут исчезнуть; Android Auto Backup отключён.
- Последний отчёт о Java/Kotlin-сбое — во внутреннем хранилище и, если доступно, в `/sdcard/Android/data/com.doxaiz.netoptimizer/files/crash.log`. Отчёт может содержать технические и личные сведения и не охватывает все типы сбоев.

Историю можно вручную экспортировать в CSV. Файл не зашифрован; выбрав облачное хранилище, вы передаёте его выбранному провайдеру. Импорт обратно в приложение не реализован.

## Зачем нужны доступы

| Доступ | Для чего | Обязательно? |
|---|---|---|
| Точное местоположение | Android использует его для предоставления сведений о соте и сигнале. Приложение не сохраняет координаты устройства. | Нет; без него часть данных о сигнале может отсутствовать. |
| История использования | Доступ к доступной Android статистике мобильного расхода по приложениям/UID. | Нет; нужен только для этой статистики. |
| Shizuku | После подтверждения: остановка выбранных приложений; в версии 1.0.2 также управление системной экономией трафика. | Нет. |
| Исключение из оптимизации батареи | Системный параметр Android. | Нет; **не включает** пока недоступные фоновые функции. |

Для статистики по приложениям в манифесте также заявлен `QUERY_ALL_PACKAGES`: Android может предоставлять приложению сведения об установленных пакетах. Помимо перечисленных выше, манифест содержит и другие разрешения для предусмотренных компонентов; их наличие не означает, что все связанные функции сейчас работают. Полный список — в [AndroidManifest.xml](../app/src/main/AndroidManifest.xml).

Доступами можно управлять в настройках Android. Доступные данные зависят от версии системы и прошивки.

## Сетевые запросы

По действию пользователя приложение обращается к сторонним серверам: TCP-проверки — к выбранным сайтам (на главной к Яндексу), спидтест — к Cloudflare, сравнение DNS — к указанным DNS-серверам. DNS-бенчмарк использует обычный незашифрованный UDP, а не проверяет Private DNS. Сетевые провайдеры и узлы могут получать техническую информацию о запросах, например IP-адрес.

Системный Private DNS пользователь настраивает самостоятельно; Android применяет его на уровне устройства, в том числе к Wi‑Fi. В версии 1.0.1 можно открыть системные настройки экономии трафика и просмотреть статус ограничения фонового трафика этого приложения. В версии 1.0.2, если Shizuku подключён и позволяет проверить состояние, пользователь может после подтверждения включить или выключить эту общесистемную настройку прямо из приложения; без Shizuku она меняется вручную в Android. Действие «Оптимизировать сеть» с Shizuku после подтверждения измеряет TCP-задержку, включает экономию трафика и делает повторный замер; если настройка уже включена, приложение не меняет её. В готовящейся версии 1.0.5 без Shizuku приложение открывает настройки Android; пользователь сам меняет системный переключатель и при желании может выполнить замер до и после. Список пользовательских приложений для ручного открытия настроек формируется на устройстве, не является списком текущей сетевой активности и не отправляется на сервер. Экономия трафика может ограничивать фоновые соединения на лимитных сетях, включая лимитный Wi‑Fi, и задерживать уведомления; исключения регулируются Android. Приложение пока не включает VPN-фильтрацию и не блокирует трекеры.
