# Android и Rust: заметки для разработки

Срез исследований: 17 ноября 2026. Эти источники описывают платформу и ограничения, а не доказывают улучшение сети или производительности приложения.

## Нативная библиотека и совместимость

- [Цели Rust для Android](https://doc.rust-lang.org/rustc/platform-support/android.html) поддерживают `std` и кросс-компиляцию через NDK. В проекте закреплены Rust и NDK; Kotlin продолжает отвечать за Android API, а Rust — за ограниченные по размеру вычисления.
- [JNI tips](https://developer.android.com/ndk/guides/jni-tips): ссылки JNI локальны для потока и вызова; `Get*ArrayElements` может вернуть копию или закрепить массив, и каждый успешный вызов требует соответствующего `Release`. Мост использует `JNI_ABORT` для входного массива, который не изменяет. Ошибки JNI при выделении памяти могут приводить к исключению: fallback не является гарантией восстановления после исчерпания памяти или аварии процесса.
- [Видимость символов NDK](https://developer.android.com/ndk/guides/symbol-visibility): для JNI с поиском по имени можно перечислить нужные JNI-символы в version script. Скрипт сборки проверяет их наличие для четырёх ABI; Rust-символы не предназначены быть общим внешним API.
- [Android: страницы 16 КиБ](https://developer.android.com/guide/practices/page-sizes): проверять следует **все** .so, включая сторонние, а не только свою библиотеку. Кроме выравнивания LOAD важно проверить случай, когда некратный 16 КиБ конец GNU_RELRO находится перед изменяемыми данными в том же сегменте. `scripts/check-native-apk.py` проверяет состав Rust ABI, сжатие, ELF машинный тип/LOAD и этот случай RELRO; для других 32-битных библиотек требование 16 КиБ не навязывается. Это структурная проверка, не полная верификация безопасности ELF и не замена реальному устройству.
- CI запускает JNI на x86_64 Android 12 и 14 и на Android 15 с образом 16 КиБ, проверяя `getconf PAGE_SIZE`. Отдельные тесты ARM64 Linux проверяют вычисления, но не являются JNI-тестом на Android ARM64. Нужны тесты на физическом ARM64-телефоне, в том числе на 16-КиБ устройстве при наличии.
- [Правила R8 для JNI](https://developer.android.com/topic/performance/app-optimization/keep-rule-examples): стандартные правила AGP сохраняют имена native downcalls. Минификация сейчас выключена; перед её включением надо проверить release-сборку и фактическую работу JNI, а не предполагать совместимость.

## Что реально измеряется

- [TrafficStats](https://developer.android.com/reference/android/net/TrafficStats): мобильные байты — суммарные счётчики по мобильным интерфейсам с момента загрузки; данные о чужих UID недоступны через `getUidRxBytes` начиная с Android 7. Суммарный мобильный трафик нельзя приписывать конкретному приложению.
- [Состояние сети](https://developer.android.com/develop/connectivity/network-ops/reading-network-state): `INTERNET` означает конфигурацию для выхода в интернет, а `VALIDATED` — последнюю успешную проверку системой. Оба состояния могут измениться; при работе с callback следует использовать его данные и своевременно снимать регистрацию. Даже validation не гарантирует доступность конкретной цели измерения.
- [Экономия трафика](https://developer.android.com/develop/connectivity/network-ops/data-saver) ограничивает фоновые данные на тарифицируемой сети, допускает пользовательские исключения и предлагает уменьшать расход даже на переднем плане. [Фоновые ограничения батареи](https://developer.android.com/topic/performance/background-optimization) зависят от устройства и могут задерживать или запрещать работу. Поэтому ручные ограничения других приложений нельзя представлять как безвредные: они могут задерживать уведомления и должны отменяться пользователем.
- [Частые сетевые запросы](https://developer.android.com/develop/connectivity/minimize-effect-regular-updates) могут удерживать радиомодуль активным и расходовать батарею. Экспериментальный KeepAlive не гарантирует состояние модема, доставку пакета или улучшение задержки.
- [Android Microbenchmark](https://developer.android.com/topic/performance/benchmarking/microbenchmark-write) требует физическое устройство для репрезентативных измерений. Сравнивать Rust и Kotlin следует на реальном устройстве, включая преобразование списков и накладные расходы JNI, на типичных размерах входа; измерения эмулятора не доказывают ускорение.

## Дальнейшая совместимость и выпуск

- На момент исследования проект использует `targetSdk = 34`. По [требованиям Google Play](https://support.google.com/googleplay/android-developer/answer/11926878?hl=en), для новых обычных мобильных приложений и обновлений с 31 августа 2026 требуется target API 36; есть отдельные правила и исключения для других форм-факторов. Это ограничение Google Play, а не требование для установки APK вне Play. Перед публикацией в Play отдельно обновить compile/target SDK и зависимости и провести полный регрессионный прогон.
- При переходе на API 36 учесть [изменения Android 15](https://developer.android.com/about/versions/15/behavior-changes-15) и [Android 16](https://developer.android.com/about/versions/16/behavior-changes-16): в частности системные отступы edge-to-edge, predictive back, адаптивные экраны, уведомления и ограничения фоновой работы. Не повышать target только ради формального соответствия без проверки UI и разрешений.
- Новая версия APK или подпись не создавались в рамках этих заметок. Исторический ключ подписи был ранее раскрыт; сохранение совместимости обновления не устраняет этот риск.
